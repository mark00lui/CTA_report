# coverage —— S3a：key_variables 的型別契約

> 本文為公開研究記錄，非投資建議。作者不揭露任何持倉資訊，
> 讀者不應假設作者持有或不持有本標的。詳見 [DISCLAIMER.md](../../../DISCLAIMER.md)。

**等級 L2**｜觸發：結構調整 S3a
**本報告不動任何標的的情境、倍數、機率或目標價。**

---

## 1. 核心不是遷移了幾筆

**是把「這一格該不該是數字」從讀者的腦子裡搬進檔案裡。**

在此之前，`key_variables` 的 schema 只寫了
「每個含 `name` / `value` / `unit` / `tier` / `source` / `updated`」——
**沒有任何地方說 `value` 該是什麼型別。** 於是：

| | 筆數 | 占比 |
|---|---:|---:|
| `value` 是數值 | 180 | 78% |
| **`value` 是散文** | **52** | **22%** |

**而那 52 筆既不算違規也不會被發現。**

現在 `kind` 必填：

| kind | `value` | `unit` | 筆數 |
|---|---|---|---:|
| `量化` | **只能是數值或 `__`** | 實際單位 | **210** |
| `質性` | 散文 | **必須寫「質性」** | **22** |

---

## 2. 六筆無損遷移，以及「無損」是什麼意思

| ticker | 變數 | 原字串 | 遷移後 |
|---|---|---|---|
| 3037 | ABF供需與漲價幅度 | `15-20` | `區間`，low 15／high 20，value 17.5 |
| 8046 | IC載板營收占比 | `近 90` | `上界`，value 90 |
| 8046 | 產能稼動率 | `逾 80` | `下界`，value 80 |
| META | 總費用guidance | `165-169` | `區間`，low 165／high 169，value 167 |
| SNDK | 漲價貢獻占季增比重 | `約三分之二` | `約值`，value 66.7（unit 質性 → `%`） |
| TSM | 全年資本支出guidance | `60-64` | `區間`，low 60／high 64，value 62 |

⚠⚠ **「無損」的定義是：`value_qualifier` 的詞彙能完整表達原字串的語意。**

**這正是設計這組詞彙的理由。** 把「約 90」直接存成 `90`、把「60-64」直接存成 `62`，
**是有損轉型 —— 它製造了原始資料沒有的精確度**，
而那與「不編造數字」是同一條規則的兩面。

| 詞彙 | 對應原文 |
|---|---|
| `點值` | 沒有修飾語 |
| `區間` | 兩端皆存，`value` 是中點（**衍生值**） |
| `下界` | 「逾／超過／以上」 |
| `上界` | 「近／不到／以下」 |
| `約值` | 「約」 |

**站台同步處理**：`kvQual()` 讓區間顯示成「167 (165–169 中點)」而非裸的 167。
**如果頁面上看不出來那是中點，那麼把它存成中點就等於在頁面上說謊。**

## 3. ⚠⚠ 七筆刻意不遷移，並標成可數的債務

```
[UNTYPED] key_variables 型別化未完成 7 筆（kind=量化 但 value 仍是散文）：
          state\2308.yaml: 變數「AI相關營收占比」
          state\2308.yaml: 變數「營益率」
          state\6239.yaml: 變數「市場共識與目標價」
          state\8046.yaml: 變數「ABF與BT漲價幅度」
          state\GOOG.yaml: 變數「股權證券損益對EPS影響」
          state\LITE.yaml: 變數「GAAP淨損的成因」
          state\MSFT.yaml: 變數「Azure成長率」
```

### 為什麼不把它們標成「質性」

**因為那是假的。**
這 7 格的 `unit` 是 `%`／`元`／`USD/股`／`百萬美元` ——
**它們本來就是數字，只是被寫成散文。**

**標成質性，會讓一個「未完成的遷移」看起來像一個「已完成的分類」** ——
而那正是這一輪從頭到尾在修的那種看不見的債。
標成 `未型別化` 則讓它每次驗證都出現。

### 兩類成因

| 成因 | 標的 | 為什麼還轉不動 |
|---|---|---|
| `value` 是**區塊純量**，裡面有大量**未被 `source` 涵蓋**的敘述 | 2308 AI相關營收占比、LITE GAAP淨損的成因 | 轉成數字會毀掉資訊 —— 例如 LITE 那格寫著「**-6,935M 但它是一次性、非現金的債務清償費用，不是營運虧損**；同期營業利益 +536.2M」，**那個轉折是這一格的全部價值** |
| `value` 裝的是**時間序列或多個量** | 2308 營益率、6239 市場共識與目標價、8046 ABF與BT漲價幅度、GOOG 股權證券損益對EPS影響、MSFT Azure成長率 | 需要 `series`／`components` 欄位 |

第二類的典型：

```yaml
value: 16.70（2026Q2）；15.15（FY2025）；11.33（FY2024）     # 2308 營益率
```

**那是三筆 `(period, value)`**，該長成：

```yaml
value: 16.70
value_qualifier: 序列最新
series:
- {period: 2026Q2, value: 16.70}
- {period: FY2025, value: 15.15}
- {period: FY2024, value: 11.33}
```

⚠ 但 `series` 一旦引入，就要同時回答「它與 `monthly_revenue` 有什麼不同」
以及「歷史要留幾筆」—— 後者正是 CLAUDE.md 對
「某個欄位長成 prepend-only append-log」的警告所指的方向。**留到 S3b 一併設計。**

## 5. ⚠⚠ 記一次操作失誤

前兩項反向測試我用 `git checkout -- state/X.yaml` 還原，
**而 S3a 當時尚未 commit —— 那把還沒提交的遷移一起還原掉了**（TSM／META／MU 三檔）。

失誤被下一次 `validate_state.py` 立刻抓到（三檔的 `kind` 變成 `None`，
噴出一串 `kind=None 不在 {量化, 質性}`），已逐檔補回並驗證「缺 kind 者 0 筆」。

**教訓：未提交的變更不可以用 `git checkout` 當復原手段。**
之後的兩項反向測試改用檔案複本（`cp state/X.yaml <scratchpad>/X.bak`）。

⚠ 值得記的是**為什麼它沒有造成損害**：因為型別契約在同一步就已經裝上了，
**所以「三個檔案掉了 `kind`」是一個會噴 error 的狀態，而不是一個安靜的狀態。**
若這次失誤發生在契約裝上之前，它會是無聲的。
