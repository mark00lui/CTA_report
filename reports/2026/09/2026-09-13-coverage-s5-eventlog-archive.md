# coverage —— S5：40 萬字元的歷史敘述自可變的 state 搬進不可改的 reports/

> 讀者不應假設作者持有或不持有本標的。詳見 [DISCLAIMER.md](../../../DISCLAIMER.md)。

**等級 L2**｜觸發：結構調整 S5 收尾
**本報告不動任何標的的情境、倍數、機率或目標價。**

## 1. 數字

| | S5 前 | S5 後 | Δ |
|---|---:|---:|---:|

縮減幅度 39 檔全部落在 **−21%（3131／8299）到 −31%（INTU／3324／MU）** 之間 ——
**沒有一檔低於兩成，這不是少數檔案的問題。**

---

## 2. ⚠⚠⚠ 依據不是「檔案太大」

**是 schema 自己原本就寫著的規定：**

> `event_log` | list | 事件流水。含 `date` / `level` / `summary` / `delta`（**一行**）。

實際做出來的是**平均 1,636 字元、最長 4,057（MU 2026-09-12）—— 超出約 27 倍。**

**而 CLAUDE.md 已經為 `coverage.yaml` 的 `equal_weight_factor_mix[].note`
裁決過完全相同的形狀：**

> 當 state 裡的某個欄位開始承擔「記錄歷史」的職責時，它就站錯地方了。

**處置也相同：搬到 `reports/`。**
⚠ 而那條裁決最重要的一句是反直覺的那句：

> 搬過去之後它才真正不可改 —— **校準價值是變強，不是變弱。**

`state/` 是可變的，`reports/` 由 `check_append_only.py` 機械強制不可改。
**一段「我當時憑什麼那樣想」的記錄，放在可以被事後修飾的地方，本來就沒有校準價值。**

---

## 3. 真正該記的是它為什麼會長出來

`delta` 寫的是「這次為什麼這樣改」。

**而那本來就寫在該事件自己的那份報告裡。**

**所以 `delta` 是把推論抄了第二份 —— 且第二份住在唯一可以被事後修改的地方。**

⚠ **它在 39 檔裡各複製了一份而沒有人注意到，正是因為每次只多寫一段，
每一次看起來都很合理。** 這與 `coverage.yaml` 那次一模一樣：
不是某一天突然做錯，是一個每次都只錯一點點的形狀。

### 一個額外的證據

`scripts/build_site.py` 全檔搜尋 `delta` —— **0 個相符。**

**這 40 萬字元從來沒有被任何讀者看到過。**
它只存在於 state 檔裡，**而 state 檔正是唯一可以被事後修改的地方** ——
既沒有讀者，也沒有不可變性保證。

## 4. 新的分工

| 東西 | 住哪裡 |
|---|---|
| 「這次改了什麼」的**一句話** | `state` 的 `event_log[].summary` |
| 「為什麼這樣改」的**完整推論** | **該事件自己的那份報告** |
| 2026-09-13 之前已寫成 `delta` 的歷史 | `reports/2026/09/2026-09-13-<ticker>-event-log-archive.md`（39 份） |

### 沿革檔的規格

`level: L0`，`signal`／`conviction`／`tp_*` 一律 `n/a` ——
**因為它不新增、不修改、不撤回任何判斷，只搬動文字。**
**原文一個字不改、不刪、不摘要。**

---

## 5. 每檔一個 commit，每檔逐項驗證才提交

**39 份沿革檔 = 39 個 commit。** 這不是形式 ——
CLAUDE.md 的理由是「不要把三檔的變更單塞進同一次提交，那會讓
`git log --follow state/3324.yaml` 失去追溯價值」，而這一輪每一檔的 state 都被改過。

每檔在提交前由程式斷言四件事，任一不符即中止：

1. 每一筆 `delta` 的**完整字串**出現在沿革檔中（逐字比對，非長度比對）
2. 事件筆數不變
3. 每一筆的 `date`／`level`／`summary` 逐一比對相同
4. state 現存 `delta` 鍵為 **0**

**39 檔全部通過。**

## 6. 閘門：防它長回來

`validate_state.py` 新增 `check_event_log()`：

```
[ERROR] state\TSM.yaml: event_log 有 1 筆帶 delta（2026-09-13…）—
        事件的細節寫在該事件的報告裡，不要寫回 state。state 是當下最佳判斷，不是日誌
```

反向測試已做（把一筆 `delta` 寫回 TSM，立刻擋下，還原後 0 error）。
`state/_TEMPLATE.yaml` 與 `state-schema.md` 同步更新。

⚠ **搬移只處理了已經發生的；閘門才是處理「它會不會再發生」的那一半。**
這一輪六個步驟裡，每一步都是這樣成對出現的。
