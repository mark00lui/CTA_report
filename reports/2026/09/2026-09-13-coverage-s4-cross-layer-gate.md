# coverage —— S4：唯一的跨層檢查併入閘門，並用孤立反向測試證明它有獨立價值

> 本文為公開研究記錄，非投資建議。作者不揭露任何持倉資訊，
> 讀者不應假設作者持有或不持有本標的。詳見 [DISCLAIMER.md](../../../DISCLAIMER.md)。

**等級 L2**｜觸發：結構調整 S4
**本報告不動任何標的的情境、倍數、機率或目標價。**

---

## 1. E4 是什麼，以及它為什麼與 E1–E3 不同

| | 比對對象 | 性質 |
|---|---|---|
| E1／E2／E3 | 單一 `state/<ticker>.yaml` **內部** | 算術自洽 |
| **E4** | **`state.weighted_tp` ↔ 該檔最新報告的 `tp_after`** | **跨層一致** |

`state` 是**可變的**（當下最佳判斷），`reports/` 是**不可改的**（由
`check_append_only.py` 機械強制）。**兩者對不上，代表其中一層被單獨改過：**

- **state 改了但沒寫報告** —— CLAUDE.md 明文禁止（「沒有報告佐證的 state 變動不該存在」）
- **報告寫了但 state 沒跟上** —— 站台與索引會繼續顯示過期的判斷

**這一類漂移在 2026-09-13 之前沒有任何機械檢查。** 它目前 39/39 相符，
**而那正是裝檢查的時機 —— 不是等它壞掉之後。**

---

## 2. ⚠⚠ 反向測試的設計才是這一步的重點

### 2.1 第一次測試證明不了什麼

把 TSM 的 `weighted_tp` 由 434 直接改成 999：

```
  [TSM] E2 weighted_tp 999 ≠ 由三格算出的 433.5
  [TSM] E4 state weighted_tp 999 ≠ 最新報告 tp_after 434（2026-09-12，…）
```

**E2 與 E4 同時響。** 這只證明 E4 會執行，**不證明它有獨立價值** ——
這個錯誤 E2 本來就擋得住，E4 在這裡是多餘的。

### 2.2 孤立測試：讓 E1–E3 全部滿意，只留下 E4

改成**內部仍然自洽**的另一組數字：

| 欄位 | 前 | 後 | E3 是否滿足 |
|---|---|---|---|
| base `eps` | 22.0 | 22.0（不動） | |
| base `exit_multiple` | 19 | **20** | |
| base `tp` | 418 | **440** | ✓ 22.0 × 20 = 440 |
| `weighted_tp` | 434 | **444** | ✓ 0.25×285 + 0.50×440 + 0.25×613 = 444.5 |

機率不動（E1 ✓）。結果：

```
=== 硬錯 ===
  [TSM] E4 state weighted_tp 444 ≠ 最新報告 tp_after 434（2026-09-12，2026-09-12-TSM-revaluation.md）

有 1 檔算術不自洽。   exit=1
```

**E1、E2、E3 全部通過，只有 E4 擋下。** 這才是 E4 存在的理由：
**一個被悄悄改過、而且改得很自洽的模型，在它之前沒有任何東西看得出來。**

測試後以 `git checkout -- state/TSM.yaml` 還原，還原後 39/39 通過。

## 3. 同樣加印涵蓋率分母

```
✓ 39 檔算術自洽（E1–E4）；E4 對照 39/39 檔；28 檔帶旗標
```

沒有對照報告的標的會列名在括號裡。

⚠⚠ **理由與 S1 的 `--stale` 完全相同，而這是同一個失效模式在這一輪出現的第三個地方**：

| 出現處 | 形態 | S 步 |
|---|---|---|
| `--stale` 的 as-of | 解析失敗 → 靜默跳過 → 空白讀起來像「都很新」 | S1（**補救**） |
| `COARSE` 21 行 | 訊息太多 → 把真正要看的行洗掉 | S2（**補救**） |
| E4 的對照範圍 | 沒有報告的標的被略過 → 空白讀起來像「都通過」 | **S4（預防）** |

**前兩次是壞掉之後才發現，這一次是在裝上去的同時就把分母印出來。**

## 4. 實作細節

`latest_report_tp()` 掃 `reports/**/*.md` 的 front-matter：

- 取 **`(date, 檔名)` 最大者**。⚠ 同日重跑會加 `-2`／`-3` 後綴，
  **字典序剛好等於正確的先後**（`…-revaluation.md` < `…-revaluation-2.md`）。
- `ticker: coverage` 略過；`tp_after` 非數值者（`n/a`、`__`）略過 ——
  沿革檔與 coverage 層報告都是那樣，它們本來就不宣告目標價。
- front-matter 解析失敗者略過：那是 `build_index.py` 的職責（它只 warn），
  這裡不重複報 —— ⚠ 但那條「解析失敗只 warn」本身仍是一個未處理的缺口，
  記在 §6。
- 容差 `max(0.51, 0.2%)`：目標價多為整數，0.51 讓四捨五入不會誤報。

---

## 5. 順序調整

計畫報告把這一步排在 S3 之後，實際提前執行。

**理由：S3 要動 232 筆 `key_variables` 的形狀，而 E4 保護的是
「state 與報告不得單獨漂移」—— 先裝上再動資料，比動完再裝安全。**
S3 若不慎改動到 `scenarios` 或 `cta.price`，E4 會在 commit 當下擋住。
