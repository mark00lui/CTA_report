# notes/ — 暫存收件匣

放**還不知道該歸到哪裡**的觀察。

state 檔要求每個變數有明確歸屬、tier、來源；driver 檔要求傳導鏈與影響清單。但很多資訊在剛看到的當下還不到那個成熟度——一則產業側聞、一個尚未成形的疑問、一個「感覺重要但說不出為什麼」的數字。

硬把它塞進某檔 state 會汙染那檔的訊噪比；直接丟掉則會失去它。所以先進這裡。

## 用法

```
/note 記憶體漲價開始影響 CSP 的 capex 組合，可能排擠 GPU 採購
/note 3017 法說提到 2027 產能，但沒說液冷占比 — 三次法說都迴避這個問題
```

一個月一個檔案：`notes/2026-08.md`，append-only，每筆帶日期與來源。

## 晉升規則

每週 `/weekly` 時回顧本月 notes，把符合條件的晉升出去：

- **同一主題出現 3 次以上** → 建 driver 檔，或成為某檔的 key_variable
- **可驗證且有數字門檻** → 晉升為某檔的 falsifier
- **只出現一次且兩個月內沒再出現** → 標記為 `[已淘汰]`，留在原檔不刪

留著被淘汰的觀察是刻意的。回頭看「我當時覺得重要但後來沒下文」的東西，比只看成功晉升的更能校準判斷力——它會告訴你自己容易被哪類雜訊吸引。

## 這裡不是什麼

不是研究報告。notes 不進 `reports/INDEX.md`，不需要結論，不需要完整來源。一句話加日期就夠了。要求太高就沒人會用，那才是真正的損失。
