# 產出模板

完整的 front-matter 與變更單版型見 `templates/report.md`（倉庫根目錄）。以下是各等級的差異。

## A. 變更單（L1 / L2）— 預設輸出，控制在一頁

結構：front-matter → 揭露句 → 等級與觸發 → 影響的變數 → 情境變動 → CTA 位階 → 訊號 → 否證點更新 → 陳舊變數與缺口 → state diff。

「訊號」一節只給三件事：評級（偏多／中性／偏空）、信心度、翻轉條件。翻轉條件必須是具體價格或事件，不是「持續觀察」。

不寫尺寸建議，不寫持倉動作用語。倉位如何配置是讀者自己的事。

## B. 全量報告（L3）— 論點層重寫

沿用變更單結構，但前面加：

```markdown
## 論點重審
**原論點**：{...}（成立於 {date}，已運行 {n} 天）
**被推翻的前提**：{哪一條，被什麼證據推翻}
**否證清單逐條檢驗**：
| 否證點 | 狀態 | 證據 |
|---|---|---|

**新論點**：{一句話} 或 **論點失效，訊號轉為偏空／中性**
**若要維持原評級，需要看到什麼**：{可驗證條件 + 期限}
```

L3 一定要給明確結論。「情況不明，維持觀察」是最貴的答案——若真的資訊不足，就寫出**要等什麼、等到什麼日期、屆時仍無解則評級如何處置**。

## C. 週報

```markdown
# CTA 推論週報｜{week}

## 本週事件流（依等級）
| 標的 | 等級 | 事件 | 訊號變化 |
|---|---|---|---|

## 覆蓋清單因子結構（等權基準）
| 因子 | 檔數 | 等權占比 | 本週是否加深 |
|---|---|---|---|

共同前提檢核：{`common_premise` 是否有新證據鬆動或強化}
`shared_falsifier` 狀態：{未觸發／接近／已觸發}

## 未來兩週檢驗點
| 日期 | 標的 | 事件 | 看什麼 | 若不如預期 |
|---|---|---|---|---|

## 陳舊追蹤
超過 90 天未更新的變數，依標的列出。

## 本週最重要的一個判斷
{一段話。若沒有值得寫的，就寫「無」— 硬湊觀點是雜訊來源}
```

## D. Dashboard 重生規範（僅 L2 / L3）

沿用既有設計系統：背景 `#0a0908`、金色強調 `#c9a449`、Fraunces serif 標題 + JetBrains Mono 數字、台股紅漲綠跌。輸出為 standalone JSX（React + Recharts），不依賴 CDN。

必備區塊：三情境機率權重條、目標價分布、關鍵變數敏感度、PE band、Fibonacci 回撤陣列、檢驗點日曆。

**不得包含**任何配置圓餅圖、部位權重長條、損益曲線——那些需要倉位資料，本倉庫沒有。

L0 / L1 不重生 dashboard——變更單即可。頻繁重繪圖表是時間黑洞，而且會讓真正的模型變動被視覺雜訊淹沒。
