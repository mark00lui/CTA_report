## 2. 腳本改了什麼

### 2.1 `parse_updated()` 取代 `as_date()` 在此處的角色

舊版把三種不同的情況壓成同一個 `None`：

```python
def as_date(v):
    if is_placeholder(v):  return None      # 根本沒填
    if isinstance(v, date): return v
    try:    return datetime.strptime(str(v), "%Y-%m-%d").date()
    except ValueError:      return None     # 填了但解析不出來
```

呼叫端 `if u and ...` 對兩種 `None` 一視同仁 —— **都是跳過**。

新版回傳三元組 `(date_or_None, precision, ok)`，讓呼叫端無法再把它們混為一談：

| 情況 | 回傳 | 呼叫端 |
|---|---|---|
| 填了但不是任何合法形式 | `(None, 'none', False)` | **error** |
| 沒填，且 `value` 也是空 | `(None, 'none', True)` | 免判定，計入分母 |
| 沒填，但 `value` 有值 | `(None, 'none', True)` | **error** |
| 日／月／年精度 | `(date, 'day'/'month'/'year', True)` | 判定陳舊；非日精度另記 COARSE |

### 2.2 精度不足取「期間第一天」

⚠ `'2026-08'` → `2026-08-01`、`'2024'` → `2024-01-01`。

**這是刻意的下界。** 取第一天會讓變數顯得更舊，於是陳舊判定**寧可多報不可漏報**；
取最後一天則會讓它顯得較新，那等同於**把一個不知道的日子補成對自己有利的樣子**，
與「不編造數字」是同一條規則的兩面。

### 2.3 `--stale` 一定印涵蓋率

**這一行存在的唯一理由是：讓「涵蓋不全」這件事本身不可能再靜默發生。**
分母對不上時腳本會另印一行要求去看 ERROR。

⚠⚠ 舊版的失效模式不是「算錯」而是「印出一片空白」，
**而空白讀起來像「都很新」** —— 那正是它能在 2026-09-12 通過整輪重校而沒被發現的原因。

## 3. 資料側改了什麼（11 筆，全部有 repo 內證據）

### 3.1 補上 5 筆完全沒有 as-of 鍵的變數

這 5 筆不是「`updated` 填了 `__`」，而是**整個 `updated` 鍵不存在** ——
`yaml.safe_load` 的 `.get('updated')` 回 `None`，於是舊版連「未填」都不會提。

| ticker | 變數 | 補上的 as-of | 依據 |
|---|---|---|---|
| 3008 | 月營收 | 2026-09-08 | `source` 明載「這一格於 2026-09-08 觸發第三條 falsifier」 |
| 3008 | 市場共識與目標價序列 | 2026-09-08 | `source` 明載「as-of 2026-09-08」 |
| 3017 | ASIC 營收佔比（管理層前瞻） | 2026-09-11 | `source` 明載「本項於 2026-09-11 全量重估時新增」 |
| 3583 | 單季淨利率（近四季） | 2026-09-10 | git blame 該行 ＝ `376f0ef0` / 2026-09-10 |
| 3583 | 自製設備與再生晶圓的合計營收占比 | 2026-09-10 | git blame 該行 ＝ `376f0ef0` / 2026-09-10 |

⚠ **最後一筆值得單獨講**：它的 `source` 寫著「公司 2026 年 6 月公開表示」。
**那是公司的發言日，不是本檔的記錄日，不可以拿來當 as-of** ——
`updated` 問的是「這一格的內容何時被更新到 state 裡」，不是「這件事何時發生」。
兩者混用會讓一個 2026-09 才寫進來的判斷看起來像 2026-06 就在追蹤了。

### 3.2 6 筆裸整數年份正規化為字串

`updated: 2026` → `updated: '2026'`。YAML 會把前者讀成 `int`，
使「精度不足」這一類在型別上分裂成 `int` 與 `str` 兩種。正規化後一律是 `str`。

## 4. ⚠⚠ 現形的 11 筆是既有債務，本報告不修

**修它們需要重新查證財報與公司揭露，那是研究工作不是結構工作**，
混在同一步會讓「結構改對了沒有」無法被單獨驗收。

它們現在**每次跑 `--stale` 都會出現**，這正是 S1 要達成的效果 ——
把一個看不見的問題變成一個吵的問題。

| 嚴重度 | 項目 |
|---|---|
| **986 天** | 3583「對台積電機台銷貨收入（2024）」—— 年精度，且資料本身標的就是 2024 年 |
| 255 天 ×5 | 3131 ×2、3363 ×2、6531 ×1 —— 全部是年精度，實際可能更新但沒記日子 |
| 135–196 天 ×5 | 6531／3211／3661／3665 ×2 —— 月精度 |

⚠ **其中「255 天」這個數字要當成下界讀**：它們的 `updated` 是 `'2026'`，
**真實更新日可能是 2026 年的任何一天**，取 1 月 1 日是保守估計。
**把它們收斂成日精度，比起去查新數字更優先 —— 因為在收斂之前，
我們甚至不知道這 6 筆到底舊不舊。**
