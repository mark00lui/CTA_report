使用者於 2026-09-07 明確選擇了「連 `/cta`、`/revalue` 也自動」的授權邊界，

- `reports/` 是 **append-only 且由 pre-commit hook 機械強制**——
  **自動化寫錯的報告刪不掉，只能再寫一份 `supersedes` 去更正，而那份也是自動寫的**

## 護欄（不可略過，違反即中止本次循環）

### G1. ⚠ 分支隔離 —— 這是最重要的一條

```bash
git checkout -b auto/$(date +%F)     # 若已存在則 checkout 既有分支
```

**所有自動化的 commit 都寫在 `auto/YYYY-MM-DD` 分支上，永不直接寫 `main`。**

> **append-only 的永久性只在 `main` 上成立。跑在分支上，錯了就砍分支。**
> 這不是把問題變小，是把「不可逆」變成「可逆」——而那是唯一真正解決它的方法。

**不 push。** 使用者的既有規則，繼續遵守。

### G2. 熔斷 —— 命中任一條即停止動模型，只寫進 `notes/inbox/`

| # | 條件 | 為什麼 |
|---|---|---|
| 1 | **算術恆等式落差 > 10%**（現價 ÷ forward PE 對上本檔 EPS） | 口徑錯置或基準年不同，2026-09-07 實測 NVDA 差 30% |
| 2 | **同一數字在兩個來源不一致，且無法判定何者為準** | 缺陷 3：不得擇一使用 |
| 3 | **量級異常**：某數字與 state 前值相差 **10 倍以上** | 單位錯誤的指紋 |
| 4 | **來源抓取失敗或回傳 JS shell／403** | 抓到的可能是殼不是內容 |
| 5 | **定級為 L3**（falsifier 觸發或 thesis 前提被推翻） | 論點層一律交人 |
| 6 | **需要改動情境機率** | 使用者已明確保留此權，`/revalue` 亦明訂 |

**熔斷時的動作**：把觸發條件與原始資料寫進 `notes/inbox/YYYY-MM-DD-halt.md`，
在本次 digest 標紅，**不寫 state、不寫 reports**。

### G3. 每日預算

```
最多處理  5 檔
最多產出  2 份 L2 報告
L3        0 份（一律熔斷交人）
```

超過即停，未處理的留在 `drivers/_queue.yaml` 的 `pending`。
**⚠ 預算用完時必須在 digest 明寫「今天漏掉了什麼」——靜默截斷會被讀成「都看過了」。**

## 步驟

### 1. 建分支並讀取現況

```bash
git checkout -b auto/$(date +%F) 2>/dev/null || git checkout auto/$(date +%F)
python scripts/daily_check.py
```

讀 `notes/inbox/` 當日檔（若機械層已寫入）、`drivers/_queue.yaml`。

### 2. 公司行動掃描（獨立步驟，**不得以新聞搜尋代替**）

依 `SKILL.md` 第 2 步執行。⚠ **2026-09-07 的自我檢查記錄**：
該日報告裡寫的「公司行動掃描」其實是報價頁新聞側欄帶出來的，**不是真的重訊掃描**。
它有效，但那是運氣。本指令執行時**必須實際去公開資訊觀測站／SEC EDGAR**，
抓不到就在 digest 明寫「本日重訊掃描失敗」，**不要用新聞頂替**。

### 3. 逐檔核實（每個要動的數字都跑）

```
① 算術恆等式：現價 ÷ forward PE = 隱含 EPS，與本檔 EPS 比對 → 落差 > 10% 熔斷
② 內部一致性：季度數字加總是否對得上年度
③ 量級檢查：與 state 前值差 10 倍以上 → 熔斷
④ 來源層級：一手（財報／法說）> 資料商 > 二手轉述
⑤ 五欄：值／來源／as-of／口徑／層級，缺一即非 load-bearing
```

### 4. 定級與處理

依 `SKILL.md` 的客觀門檻。**L0／L1／L2 自動處理，L3 熔斷交人。**
處理時完整走 `/cta` 或 `/revalue` 的流程，含步驟 1b 的方法組合複核。

**機率一律沿用前值並標「機率沿用前值，未重評」。**

### 5. 驗證與 commit（在分支上）

```bash
python scripts/check_public.py && python scripts/check_append_only.py \
  && python scripts/validate_state.py && python scripts/cross_check.py \
  && python scripts/build_index.py && python scripts/build_site.py
```

任一失敗 → **中止並保留現場**，不要試圖繞過。
commit message 照既有格式。**不 push。**

### 6. 寫當日 digest

`notes/inbox/YYYY-MM-DD-digest.md`，五節，每節都要有：

1. **做了什麼** — 逐檔列出等級與目標價變動
2. **⚠ 熔斷了什麼** — 觸發哪一條、原始資料是什麼
3. **⚠ 預算用完漏掉了什麼** — 沒有就寫「無」
4. **⚠ 本日最不確定的一個判斷** — 一句話，硬湊是雜訊
5. **人該看哪一檔** — 最多三檔，附理由

### 7. 回報

輸出分支名與 digest 路徑。**合併與否由使用者決定。**

```bash
git log --oneline main..HEAD          # 本次做了什麼
git diff main --stat                  # 動了哪些檔
```

## 注意

**這個指令的價值在於它每天都跑，不在於它每天都產出。**
多數日子的正確結果是「檢查完，沒有值得動模型的事」——
那時 digest 只有第 1 節寫「無」，其餘照寫。

**⚠ 不要為了讓 digest 看起來有產出而升級任何一檔。**
`/brief` 已記過同一個毛病：「不要為了讓佇列看起來有產出而升級」。

**⚠ 熔斷不是失敗，是這個系統唯一的安全閥。**
熔斷次數應該被記錄並定期回顧——若某條熔斷從不觸發，它可能設得太鬆；
若某檔反覆熔斷在同一條，那是資料源的問題，該修的是來源不是門檻。
