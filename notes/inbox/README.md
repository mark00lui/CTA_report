# notes/inbox/ — 機械層的收件匣

**只有機器寫這裡。** 自動化流程（GitHub Actions 與 `/auto-cycle`）的產出全部落在這個目錄。

## 為什麼是這裡，不是別的地方

| 目錄 | 保護機制 | 機器可否寫 |
|---|---|---|
| `reports/` | `check_append_only.py` 機械強制，**已 commit 的不可改不可刪** | ❌ 錯了刪不掉 |
| `state/` | 每次改動必須有對應報告 | ❌ 需要判斷 |
| `drivers/` | 單一真相來源，錯了會扇出到全清單 | ❌ 需要判斷 |
| **`notes/inbox/`** | 無 | ✅ **可覆寫、可刪除** |

`notes/README.md` 早就把 `notes/` 定義為「還不知道該歸到哪裡」的暫存區——
機械層的產出正好符合這個語意：**它是原料，不是結論。**

## 檔案類型

```
YYYY-MM-DD.yaml         收集層的原始素材  ⚠ 只存原文＋URL＋取得時間，不做摘要
YYYY-MM-DD-check.md     每日機械檢查報告（scripts/daily_check.py）
YYYY-MM-DD-halt.md      ⚠ 熔斷記錄 —— 觸發了哪一條、原始資料是什麼
YYYY-MM-DD-digest.md    /auto-cycle 的當日摘要
```

## ⚠ 為什麼收集層不做摘要

2026-09-01 一輪工作中二手來源錯了六次，**其中四次錯在摘要階段**：

- 「2027 資本支出約 4 billion」——正確是台幣 400 億，**10 倍單位錯誤，且會把結論反過來**
- 「FY2027 EPS 58.05」——與同期單季 EPS 25.11 直接矛盾，口徑錯置
- 「景碩 3413」——3413 是京鼎，景碩是 3189

**存原文，判斷層才有機會抓到口徑問題。摘要一旦寫進來，錯誤就失去了被發現的機會。**

## 保留政策

這個目錄可以定期清理。它不進 `reports/INDEX.md`，不需要保存 ——
**真正該留下的東西會被判斷層晉升到 `drivers/`、`state/` 或 `reports/`。**
⚠ 但 `-halt.md` 例外：熔斷記錄應保留並定期回顧，它是校準這套自動化的唯一素材。
